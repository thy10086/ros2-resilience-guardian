# Jev 事件会话与软证据绑定设计

版本：0.2（离线工程实现，2026-09-23）

## 目标

`JevEfficientJudge` 解决重复请求和并发合并后，系统仍需要一个跨时间的事件层：连续告警属于同一事件时应共享判断，风险突然变化时应重新判断，Jev 结果过期后不能继续刷新账本证据。

`JevIncidentSession` 位于高效判断层和 `EvidenceLedger` 之间。它不改变确定性 Guardian 安全状态机的权限，只负责事件聚合、查询时机、判断滞回和 Jev 软证据审计。

## 会话状态

- `OBSERVING`：本地风险和语义建议没有达到人工复核阈值。
- `REVIEW_REQUIRED`：Jev 建议人工复核、Jev 与本地规则冲突或有效分数超过进入阈值。
- `CONTAINING`：本地安全状态为 `CONTAINING`/`SAFE_STOP`、风险输入非法，或账本完整性/父证据校验失败。
- 会话超过 TTL 后会重新建立，旧会话不会延长其软证据寿命。

从 `REVIEW_REQUIRED` 回到 `OBSERVING` 需要安全状态为 `NORMAL`、有效分数低于退出阈值，并持续满足稳定窗口。这个滞回避免 Jev 结果在相邻观测中来回翻转。

## 查询门控

同一 `incident_key` 的事件在最小查询间隔内复用上一次会话判断。以下情况会强制重新查询：

- 风险变化超过 `risk_change_trigger`；
- 攻击类型、时序码、活动组件、安全状态或来源验证状态发生语义变化；
- `graph_risk`、`mission_criticality`、`event_confidence` 的规范化数值发生变化；
- 当前事件的 `parent_evidence_id` 发生变化，需要重新验证父链并重新绑定软证据；
- 最小查询间隔已到期；
- 会话没有历史判断或超过 TTL。

事件 ID 和序列号不会改变会话身份，避免告警洪泛把同一事件拆成多个请求。

会话签名复用 `SemanticContext.to_state()` 的清洗和字段上限：组件、攻击类型、安全状态、时序码和活动组件均使用有界文本，时序码和活动组件去重后排序；图风险、任务关键性和事件置信度保留有限数值或非法标记。自由文本摘要、事件 ID 和序列号不进入签名。这样远程请求边界和本地会话边界使用相同的输入预算，超长或控制字符不会放大会话层的哈希和集合操作。

`source_verified` 使用严格类型语义：只有原生 `bool` 才进入签名；非布尔值被记录为非法并强制重新判断。`False` 和非法来源都走 `SKIPPED_UNVERIFIED` 本地路径，状态进入 `CONTAINING`，不会发起远程请求，也不能复用之前已验证会话的 Jev 结果。

观测时间也有 fail-safe 规则：显式时间无法转换或不是有限数值时，使用注入的内部时钟；只有内部时钟同样无效时才回退到 `0.0`。同一会话的较早时间会被钳制到 `last_seen`，不允许时间线倒退。这样调用方的格式错误不会让会话异常退出，也不会把未来或倒退时间写入软证据。

## 软证据约束

只有成功且有界的 Jev 结果才会写入账本，记录特征为：

- `source="jev"`、`kind="semantic_advice"`；
- `parent_ids` 指向已经验证且策略版本一致的确定性事件证据；
- 有独立的短期 `expires_at`；
- `hard_stop=False`，不能清除或替代硬停车证据；
- 账本完整性失败、父证据缺失、provider 失败、预算耗尽时不写入。

重复会话复用不会刷新旧软证据的过期时间。父证据切换时，即使高效判断层命中 Jev 缓存，也只允许把成功的有界语义结果重新绑定到新父证据；普通缓存复用不会追加记录。账本被篡改时，即使当前事件本地判断为低风险，也会直接返回 `LEDGER_BLOCKED/CONTAINING`，不向 Jev 发起请求。

## 并发和容量边界

每个会话拥有独立锁，完整的“读取记录—查询或复用—账本追加—状态写回”在同一会话内串行执行；不同 `incident_key` 仍可并行，避免全局锁包住远程请求。账本层另有一个短临界区锁，只包住 `verify()+append()`，防止不同会话同时计算同一前置哈希，不会串行化远程判断。会话表通过 LRU 淘汰保持 `max_sessions` 上限，账本异常分支也遵守同一上限，防止持续故障导致内存无界增长。
