# 前端恢复轨迹检测

从“恢复验证”进入“安全测试分析”（`#research`），默认显示轨迹检测；“仿真验证 → 事件回放”也可通过“恢复轨迹检测”跳转。页面按任务分为“轨迹检测 / 多智能体研判 / 实验记录”，每次只显示一种方式。旧工作区地址继续可用，`#research/agents`、`#research/evaluation` 可直接打开对应视图。

顶层导航收敛为五组：安全检测（单文件检查、多文件安全图、数据集审计）、恢复验证、仿真验证（事件回放、ROS 2 闭环、代码沙箱）、运行监控、模型服务。单一工具分类不再显示重复的次级导航。

源码检查可将当前编辑文本带入安全图或多智能体研判；安全图可带入当前文件列表；轨迹检测可带入当前已加载帧。带入只更新浏览器中的输入并显示来源，用户点击运行后才提交；进行中的多智能体任务拒绝被新输入替换。切换研判输入会清除旧结果与下载入口，编辑源码、替换安全图输入后迟到的旧请求也不能覆盖当前输入的结论。

四角色入口填写 OpenAI 兼容 URL、API Key 和模型名，支持读取模型列表、运行、取消与下载；使用与限制见 [多角色闭环](artex_ros2_agent_review.md)。它在六项固定目录内规划，新执行只针对自有虚拟恢复模型；不能把上传项目的静态风险改成已通过。下载保留服务端 JSON 数值表示，以便重算报告内摘要。

## 使用

1. 登录后选择恢复样例并点击“加载样例”，或导入JSON/JSONL文件。
2. 点击“检测恢复轨迹”。结果展示实际检查帧数、违规总数、状态/转移覆盖、活性采样空窗，以及违规帧的公开图/策略/账本/消费许可绑定。
3. 如需模型规划，点击“带入多智能体研判”，确认输入来源并填写接口后手动运行。仅需已有轨迹断言检查时，无需 API Key。
4. 切换“实验记录”查看五组对照表及折叠详情，了解实际优化目标、配对索引和原始误报修正。该表来自历史验证快照，点击检测不会运行50,000次搜索；既有Jev离线自检也放在该视图的折叠区。

六个内置样例由现有场景/已保存资格轨迹导出：正常恢复、六次控制暂停后恢复，以及取消TTL/上下文/一次性/独立观测约束产生的四类受控缺陷。受控轨迹只用于检测示范，不会把变异代码加载到ROS节点，也不是四个生产漏洞。

支持格式：RecoveryFrame对象数组、带 `frames` 数组的反例报告，或逐行JSON的ROS审计日志。混合日志中只取 `kind="recovery_trace"` 行，并去掉kind后验证完整帧字段；缺少 `observed_speed`、`pending_proof`、`consumed_proof_id` 等任何帧字段均拒绝，不能将未知速度当成零。缺少恢复帧、空数组、字符串布尔值、未知恢复阶段和非正许可寿命也拒绝。最多2000帧、2MiB；导入或请求失败隐藏旧结果，检测期间锁定输入，延迟到达的样例列表不能切换正在检测的轨迹。NORMAL 状态同时检查实际输出 `next_command_epoch` 与当前授权一致。

`POST /api/recovery/inspect` 沿用登录保护，严格仅接收 `{"frames": [...]}`。后端直接调用 `RecoveryFrame`、`SafetyOracle`、`SemanticCoverage`，没有另写恢复判断、调用Jev、签发许可或发布控制命令。返回 `NO_VIOLATIONS` 只表示提交帧未触发断言，无法认证日志来源，也不等于物理安全或安全认证。最多展示前100条违规，计数涵盖全部。

活性窗口为3秒，相邻帧间隔大于0.25秒只重启连续活性计时；等于0.25秒仍连续。采样空窗不用于推断连续健康，授权、时效、上下文和重放检查继续执行。检查参数由后端实际Oracle返回，用户不能在请求里降低阈值。

## 快照来源与更新

`frontend/recovery-evaluation.json` 保存从第六轮修正报告导出的aggregate、预算、种子、目标标签、Oracle参数、重放计数和摘要SHA；`recovery-samples.json` 保存六个公开审计轨迹。两文件随现有frontend资源规则打包，因此运行页面无需访问忽略Git的实验目录、Hypothesis环境或执行变异。

更新时使用既有实验环境：

```bash
output/recovery-fuzz-venv/bin/python experiments/export_recovery_dashboard.py \
  experiments/results/feedback_target_ablation_corrected/summary.json
bash deploy/run_guardian.sh build --distro humble
```

导出器核对完整五组预算、种子配对、零预热、全机制/资格控制及重放验收、重新聚合结果、冻结源码SHA和Oracle实际参数；有失败或来源变化会拒绝导出。它复制实际报告统计，不在前端手写检出率；样例用现有Oracle核对后才保存。运行中的旧Dashboard进程需要重启才能加载新Python检测接口，浏览器刷新后读取新资源；无需安装系统服务。

第六轮结果仍为TTL检出5/4/7/6/4（各10种子），其余三族各10/10，184反例/50语料重放一致。完整边界反馈在本批次TTL指标改善但总转移覆盖下降，第五轮方向不同；raw与corrected是相同种子重跑，不合并为独立样本。详见 [第六轮报告](feedback_target_ablation.md)。
