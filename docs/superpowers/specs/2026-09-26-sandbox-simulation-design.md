# 机器人代码沙箱仿真设计

## 目标

让用户导入控制机器人用的 Python 或 SDF/URDF 文件后，得到可复核的运行证据，而不是只有静态规则结论：

- Python 控制器在隔离子进程中按固定控制周期运行。
- SDF/URDF 只作为明确的机器人/场景描述解析，不把任意 XML 当作可执行程序。
- 记录请求速度、施加速度、位姿、障碍距离、超速、运行时异常、超时和碰撞等证据。
- 用同一份服务器生成的证据摘要调用 Jev，Jev 不能接收完整源码，也不能改变 Guardian 的本地结论。

## 输入契约

### Python

上传文件必须定义以下函数之一：

```python
def control(state):
    return {"linear_x": 0.2, "angular_z": 0.0}
```

`state` 只包含时间、位姿、障碍距离、速度边界和安全许可。控制器不能直接连接 ROS 2、网络、文件系统、进程或动态执行接口。运行时使用固定白名单 builtins 和模块。

### XML

只接受根节点为 `sdf` 或 `robot` 的 SDF/URDF。禁止 `DOCTYPE`、外部实体、外部 URI、`plugin` 和 `include`。SDF 在本机存在 `gz` 时额外使用 `gz sdf --check` 校验，但不加载用户插件。

XML 的执行语义是“模型验证 + 内置安全控制器”，不伪称执行了用户 Python 控制代码。

## 隔离边界

优先选择可用的 Docker daemon；当前 WSL 环境使用 `unshare --user --mount --pid --net` 的受限子进程，配置 CPU、地址空间、文件大小、进程数、打开文件数和输出限制，并且关闭网络命名空间。

这是面向本地工程测试的隔离，不是对抗恶意多租户代码的 VM 边界。结果必须展示隔离提供方和边界，沙箱不可用时直接失败关闭，不能回退到 Dashboard 进程执行上传源码。

## 报告

报告至少包含：

- `source_sha256`、文件名、输入类型；
- `sandbox.provider`、是否隔离、网络是否关闭、边界说明；
- `engine`、固定步长、总时长；
- `metrics`：步数、最大请求速度、最大施加速度、超速步数、最小障碍距离、碰撞步数、运行时错误；
- `events`：带时间、严重程度和可读证据；
- `trace`：有限长度轨迹，供前端绘图；
- `verdict`、`risk_score`、`safety_score`；
- `jev`：只包含证据摘要的可选语义判断。

“通过”只表示在当前固定场景、固定时间步和当前隔离边界下未观察到指定风险，不代表实机认证。
