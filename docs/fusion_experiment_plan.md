# 跨层融合实验计划

本文档描述下一阶段研究型扩展的实验设计。它是计划，不代表图传播、时序规则、安全速度包络或恢复门控已经在当前仓库实现。

## 研究目标

把当前的“可信事件 + 任务韧性”扩展为跨层证据融合：同时使用 ROS 2 节点/话题图、消息时序、身份策略、任务阶段和物理安全约束，决定是否允许任务继续、降低速度、隔离组件或停车。

参考方向：

- [RobResilience](https://arxiv.org/abs/2609.17349)：提供 `delta`、`gamma`、`mu` 和攻击场景基线；
- [RIPS for ROS 2](https://arxiv.org/abs/2412.19272)：提供 ROS 2 入侵防护、规则和威胁模型思路；
- [ROSMonitoring 2.0](https://arxiv.org/abs/2411.14367)：提供有序话题、服务和运行时验证思路；
- [Resilient Control Loops](https://arxiv.org/abs/2609.05739)：提供通信层和控制层联合恢复思路；
- [SROS 2](https://github.com/ros2/sros2)：提供 DDS 身份和访问策略基础。

## 对照组

- `B0`：论文兼容的 `delta / gamma / psi` 和原始场景；
- `B1`：当前项目的零信任事件验证、多波重新规划和安全状态机；
- `B2`：加入图传播、时序规则、证据融合和安全速度包络的完整方案。

所有对照组使用同一组攻击时间线和任务目标，避免把场景差异误认为方法收益。

## 实验 A：ROS 2 图传播

构造导航节点、传感器节点、速度控制器和底盘执行器的有向图。分别攻击普通感知节点、导航节点和底盘控制入口，比较风险是否沿发布者—话题—订阅者路径传播到执行器。

记录：

- 被影响的节点和执行器数量；
- 图更新延迟；
- 关键执行器的风险提升；
- 与只看事件组件的 `B1` 结果差异。

成功判据：攻击路径上的关键执行器不能保持 `NORMAL`，无路径组件不会被无理由停车。

## 实验 B：时序规则和运行时验证

用 YAML 定义消息新鲜度、频率、顺序和来源规则，例如“传感器新鲜度超过阈值后，导航节点不得继续发布运动指令”。注入乱序、重复、低频、突发和错误来源消息。

记录：

- 每条规则的命中原因；
- 检测延迟；
- 误报率；
- 是否触发降速、隔离或停车。

成功判据：违反安全时序的消息被标记为证据，合法但低频的非关键消息不会直接触发全车停车。

## 实验 C：多源证据融合

对同一攻击分别提供合法签名、错误签名、可信来源但异常时序、低置信度 IDS 结果和高关键度执行器路径。比较只使用事件置信度与融合身份、时序、图关键度后的决策。

建议把融合项保持为可配置参数，并做消融实验：

1. 去掉身份证据；
2. 去掉时序证据；
3. 去掉图关键度；
4. 使用完整证据集合。

记录：残余风险、误停车率、关键攻击漏报率、风险解释字段和计算耗时。

## 实验 D：安全速度包络

在室内导航仿真中改变障碍物距离、制动能力、传感器新鲜度和风险等级，比较固定速度策略与风险/制动距离约束策略。

实验不能只看速度是否下降，还要检查：

- 停车距离是否小于可用距离；
- 传感器过期时是否禁止提速；
- 风险恢复后是否经过恢复门控才恢复速度；
- 安全约束是否造成过多无必要停车。

## 实验 E：恢复门控

攻击节点发送“恢复正常”消息时，分别保持旧命令、旧图连接、过期传感器或未通过策略检查。只有攻击消失、图稳定、传感器新鲜、旧命令清空和策略通过时，才允许从 `SAFE_STOP` 或 `CONTAINING` 恢复。

记录恢复时间、拒绝原因、旧命令是否被执行和恢复后的第一条有效控制命令。

## 统一指标

- 攻击接受率和拒绝率；
- 检测到隔离的延迟；
- 误停车率；
- 任务完成率；
- 残余风险；
- 安全速度违规次数；
- 恢复时间；
- 图更新、规则检查和风险融合的 CPU/内存开销。

## 实施边界

第一阶段只使用 ROS 2 graph introspection、离线图和 Webots 可替换接口，适配单台笔记本。SROS 2 真实证书、DDS 策略和底盘控制需要单独的集成实验。在线安全决策不依赖大语言模型；图记忆或自动攻击生成只能作为离线测试工具。
